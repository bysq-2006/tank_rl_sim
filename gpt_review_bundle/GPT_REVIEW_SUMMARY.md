# 坦克强化学习代码审查说明

请直接检查本文件夹中上传的 Python 文件，不要假设可以访问我电脑上的原始路径。

## 目标

用 PPO 从零训练坦克 AI，使其能观察地图、判断敌人位置、瞄准开火、躲避子弹，并在有墙体和子弹反弹的环境中击杀敌人。

目前的明显问题是：模型经常持续旋转、持续后退、乱开炮，几乎不会根据敌人位置瞄准，也不会主动躲避子弹。请重点找出代码级原因，并给出具体修改方案。

## 代码文件对应关系

文件名中的 `__` 代表原始路径分隔符：

- `rl__model.py`：actor-critic 模型
- `rl__observation.py`：地图、坦克、子弹观测构造
- `rl__rewards__reward.py`：奖励和势函数
- `rl__envs__tank_env.py`：RL 环境封装
- `rl__envs__scenarios.py`：关卡出生和场景设置
- `rl__curriculum__config.py`：课程关卡和奖励配置
- `rl__curriculum__manager.py`：课程晋级和对手抽样
- `rl__training__ppo.py`：PPO 更新
- `rl__training__rollout.py`：采样和轨迹处理
- `core__game.py`：坦克、子弹、墙体和碰撞物理
- `core__entities.py`：实体定义

## 模型结构

地图输入是 `2 x 96 x 96`：墙体通道和有效地图掩码。CNN 为 `2 -> 32 -> 64 -> 32`，步幅为 2，展平后经过 `4608 -> 2048 -> 1024`，得到 1024 维地图特征。

自身只有 4 维：绝对 x/y、朝向的 cos/sin，经过 `4 -> 32 -> 32`。

最多 3 个敌方坦克，每个 4 维：相对 x/y、相对朝向 cos/sin，经过 `4 -> 32 -> 32`，再用 masked sum + masked max 汇总成 64 维。

最多 15 颗子弹，每颗 4 维：相对位置 x/y、相对速度 x/y，经过 `4 -> 64 -> 64`，再用 masked sum + masked max 汇总成 128 维。

融合为 `1024 + 32 + 64 + 128 = 1248` 维，再经过 `1248 -> 768 -> 512`。策略头为 `512 -> 256 -> 18`，价值头为 `512 -> 256 -> 1`。

动作是 18 个离散联合动作：油门 3 种 × 转向 3 种 × 开火 2 种。

## 观测中可能缺少的信息

- 自身速度和角速度
- 开火冷却时间
- 炮塔或炮口独立朝向
- 子弹预计碰撞时间和是否朝向自身
- 子弹的敌我归属
- 历史帧或短期记忆

敌人和子弹使用 sum/max 汇总，可能丢失具体个体之间的关系。

## 当前奖励

- 获胜约 `+1`
- 失败、死亡、超时为负奖励
- 击杀奖励按关卡配置
- 使用距离、朝向、视线无遮挡组成的势函数
- 预测子弹轨迹进入敌人扩大圆形范围：小额正奖励
- 预测无法接近敌人：小额负奖励
- 预测反弹后会击中自己：自伤惩罚

轨迹预测会模拟子弹飞行和墙体反弹。现在仍然出现乱射，说明奖励可能没有正确传递到瞄准动作，或者动作/观测结构本身让旋转和后退更容易成为局部最优。

## 已观察到的局部最优

1. 开局连续开数枪，容易被自己的反弹子弹击杀。
2. 原地旋转并随机开火。
3. 持续后退并开火。
4. 对静止敌人偶尔碰巧命中，但没有真正学会瞄准。

第 1 关以前使用 `idle` 对手，敌人不移动也不攻击，因此不能真正教会躲避子弹；第 3 关使用会移动和简单躲避的对手。

## 请重点分析

1. 观测是否足够表达敌人、子弹和自身运动状态；
2. 18 个联合动作是否导致探索困难；
3. 油门、转向、开火是否应该拆成独立动作头；
4. sum/max 实体汇总是否丢失了关键关系；
5. 势函数和轨迹奖励是否可能鼓励后退、旋转或乱射；
6. 子弹轨迹奖励的延迟信用分配是否正确；
7. 课程关卡和对手是否提供了正确的学习信号；
8. 是否需要 RNN/LSTM、历史帧、动作掩码或更合理的动作持续时间；
9. 给出优先级明确、可以直接修改代码验证的方案。
